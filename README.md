# AI-assisted research paper workflow

一组可独立调用的 Codex skills，用于把研究问题、数据证据、文献理解和论文表达连成可追溯的论证过程，并提供一个针对科研框架图的设计与代码重建流程。

这不是要求每次写作都走完全部阶段的流水线。可以只调用一个 skill 完成当前需要的工作，也可以在一个研究项目中逐步使用多个 skill。核心做法是先确认研究问题与证据，再规划文章的论证层级，最后按用户指定范围写作和检查。

## Skills

| Skill | 适合的请求 | 主要产物 |
|---|---|---|
| `research-story` | 讨论研究问题、贡献、科研故事是否成立 | 研究主线、问题—方法—证据—结论链、待确认问题 |
| `research-evidence` | 汇总数据、实验、分析和主张之间的支持关系 | 可追溯的证据台账、证据强度与缺口 |
| `literature-reading` | 查找、精读、比较近年或代表性文献 | 文献地图、逐篇阅读记录、可复用写作观察 |
| `manuscript-writing` | 规划或撰写论文各部分、做局部修改与全文一致性检查 | 章节—段落—句子规划、分块草稿、整合问题清单 |
| `framework-figure` | 设计方法框架图、写生图提示词、审核连接或重建可编辑图 | 模型规范、参考图分析、提示词、连接规范与矢量图 |

在支持 skills 的 Codex 环境中，可在请求中直接点名 `$research-story`、`$research-evidence`、`$literature-reading`、`$manuscript-writing` 或 `$framework-figure`。例如：

```text
使用 $research-story 和我梳理这项研究要解决的问题。先通过少量问题了解研究背景、数据和已有发现，再一起确认主线，不要直接替我写引言。
```

```text
使用 $literature-reading 查找近三年与这个研究问题最接近的论文。请区分已核验的原文信息、摘要信息和推断，并整理可复用的研究现状逻辑。
```

```text
使用 $framework-figure 阅读我的模型说明和参考论文图，先列出不可改变的模块与连线，再生成供图像模型使用的提示词。
```

## 推荐的项目推进方式

```text
研究故事 ↔ 证据台账 → 文献理解 → 章节与段落规划 → 分块起草 → 全文整合
                                      ↘ 框架图设计、审核与代码重建
```

流程可以因项目状态调整。例如已有完整实验结果时，可以先整理结果和方法证据，再回头写引言。文献检索、证据核对、图表设计和正文写作各自都可以单独调用。

## 项目记忆与可复用材料

建议在研究项目中保存短而可更新的记录，而不是依赖聊天窗口长期记住所有细节。可按需要创建：

- `project.md`：当前问题、稿件版本、作者已确认的决定和下一步。
- `research-story.md`：研究问题、假设、贡献以及证据支持边界。
- `evidence-ledger.md`：主张、数据或来源、结论强度和待核查项。
- `literature-map.md`：文献主题、代表论文、已读范围和写作观察。
- `manuscript-plan.md`：章节、段落任务、句子功能和图表关系。
- `drafts/`、`figures/`：稿件版本和图件材料。

这些是建议的项目记录名，不是强制模板。按用户指定目录工作；没有指定时再使用独立的 `manuscript-workspace/`。已有的用户记录和手动修改稿优先于旧的 AI 草稿。

## 文献阅读在工作流中的作用

定向阅读能改善当前任务的证据质量和领域表达：帮助识别研究路线、代表方法、争议、近期进展，以及论文如何安排相关工作。阅读本身不会让模型在以后所有对话中永久掌握这些知识，因此应把可复用的阅读结果保存为有来源的文献地图或范例分析，并在后续写作时重新读取。不要为了“读得多”堆砌论文；按当前论点选经典工作、最接近研究和近期代表研究，并记录实际读到的是摘要、全文还是图表。

## 科研框架图流程

1. 依据确认过的方法说明和相关论文图，Codex先整理模型模块、分支、输入输出与连线，再编写图像生成提示词。
2. 用图像生成模型探索布局和视觉表达，候选图用于讨论设计，不直接视为方法定义或论文最终插图。
3. Codex对照模型规范逐条审核生成图。若多轮后仍反复出现同类科学连线错误，冻结结构，转用可编辑代码绘图。
4. 按科学连接表重建为 SVG 等可编辑图件，再检查实际论文尺寸的文字、图例、裁切和连线。

该流程针对方法框架示意图。性能曲线、柱状图、热图等定量图必须从真实数据用绘图工具生成，不能由图像模型伪造数值。

框架图 skill 自带通用 JSON 流程连接校验器。它只检查图结构与作者声明的约束是否一致，不能证明这些约束忠实于模型；科学含义仍要对照确认过的方法和来源人工审核。

## 安装与发布

本仓库将五个 skill 放在 `skills/` 下，便于共同维护或作为插件包的源码。若要在本地 Codex 项目中使用，将需要的 skill 文件夹复制到该项目的 `.agents/skills/` 目录；若希望跨项目使用，可按 Codex 当前支持的个人 skills 安装方式部署。Skills 的目录发现和插件打包方式可能随 Codex 版本变化，发布或安装时请核对 [OpenAI skills 文档](https://developers.openai.com/plugins/build/skills) 和 [插件结构说明](https://developers.openai.com/plugins/concepts/plugins)。

项目仓库：[icybinbin/research-paper-workflow](https://github.com/icybinbin/research-paper-workflow)。仓库当前尚未指定开源许可证。使用这些 skills 处理自己的研究时，请将私人数据、个人路径、未公开结果和不能再分发的论文全文保存在个人项目中。

## 来源与设计依据

Skills 按照 OpenAI 关于 skills 的渐进式加载和按任务拆分原则组织：每个 skill 有独立的 `SKILL.md`，需要较长细节时再读取同目录 `references/`。详见 [Build skills](https://developers.openai.com/plugins/build/skills) 和 [Plugin concepts](https://developers.openai.com/plugins/concepts/plugins)。
