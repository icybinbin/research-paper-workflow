# 框架图设计与重建

将方法结构转化为可理解、可编辑、计算关系正确的框架图。支持设计、提示词、审核或代码重建中的任一阶段。

## 路由

- 设计或生图提示词：读取 [参考图分析与提示词](references/design-and-prompt.md)。
- 审核参考图、冻结连接或代码重建：读取 [科学连接与重建](references/connectivity-and-rebuild.md)。
- 使用连接检查脚本时：读取 [连接规范](references/graph-schema.md)。

## 科学依据

先从作者确认的方法和必要的实现说明中确定模块、输入输出、节点特征、编码路径、表示与预测、融合方式。仅在这些内容存在歧义时定向检查代码，不重新审计所有实验。

建立 `model-spec.md` 和连接表。参考图片提供布局、风格与图标，确认的方法与连接表决定科学内容。图中数据图的边和计算流程的箭头应有清晰区别，不能无依据地暗示因果关系。

## 工作流程

1. 阅读同方向的代表性框架图，具体分析创新突出方式、数据与网络层级、并行分支、颜色含义、图注分工及哪些特点适合当前研究。尊重作者指定的数量和参考范围。
2. 编写提示词，明确不可改变的模型关系与可调整的视觉设计。生图模型名称可配置，不假定某个工具或产品名称始终可用。
3. 请求包含生成时使用可用生图工具；由作者在其他窗口生成时提供完整提示词。仅设计或审核的请求不自动启动生成。
4. 审查候选图的遗漏、错连、串并联、重复输出和无来源模块，形成修改清单。
5. 当构图已经可用而多轮修改反复出现同类科学错误时，记录错误并转入代码重建；通常两三轮足以判断。若作者授权重建，直接执行，不继续无限追加生图提示词。
6. 重建尽量还原选定视觉设计，纠正已知科学错误。不得为像素相似保留错误箭头。保留可编辑文字、矢量图形和生成源文件。
7. 先检查连接，再检查论文实际尺寸下的文字、间距、导出与裁切。只有满足科学规范且阅读清楚才交付。

## 重建方式与检查

遵循作者已选择的绘图语言或工具。未指定时，可使用直接生成 SVG 的代码方案；如要使用其他绘图 skill，遵守其适用要求。图像编辑使用可用生图工具，不以像素处理冒充可编辑重建。

连接表可使用 `graph-spec.json`，通过本 skill 的 `scripts/validate_graph.py` 检查节点、连接、禁连和输入输出约束。脚本通过不能证明图与方法一致，还须检查实际渲染箭头，并核对每条箭头的来源与终点。

## 交付

在作者指定的图目录或 `manuscript-workspace/figures/` 保存相关产物：模型规范、参考图分析、提示词、草图审核、源文件、SVG/PDF和预览。仅交付当前阶段需要的文件，记录参考图与最终图之间的科学修正。

这套生图—审核—重建流程用于框架与方法示意图。实验柱状图、曲线、统计热图等直接使用真实数据绘制，不能从生图模型取得数值图。
