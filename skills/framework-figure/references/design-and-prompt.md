# 框架图设计与生图提示词

## 先分析，再描述视觉

先读取作者确认的方法说明、模型结构和必要代码片段，再阅读与研究方向相近的高质量论文图。优先分析图怎样传递方法，而非只摘取配色：

- 输入、预处理、图/模块、编码器、融合和预测在图中的顺序。
- 主干与并行分支如何区分，分支在哪里产生、在哪里汇合。
- 节点、边、特征、图卷积、分类得分等符号怎样表达，哪些是示意元素。
- 颜色和线型是否有稳定含义，图例是否能在同一图面内解释。
- 哪些信息放主图，哪些留在图注或方法正文。

参考论文须经来源核实。记录文章题目、期刊/年份、图号与 DOI/URL，并把观察到的图形设计原则转成自己的话。不能将论文原图直接交给生图模型要求照抄，也不能据“顶刊风格”推断某种设计规则具有普遍性。

## 建立模型规范

在提示词前写 `model-spec.md` 和连接表，至少包括：模块清单、每个模块的输入和输出、共享与独立参数、并行/串行关系、分支融合、输出类别，以及必须保留和禁止暗示的关系。单列待确认项，未确认事实不写进生图提示词。

对候选图逐项检查连接：哪条箭头从哪开始、经过什么、到哪里结束；计算箭头和图内患者/基因关系边分开定义。指定样本数、节点数、示意数据仅在准确性有必要时；示意图必须标明其为示意。

## 编写可执行提示词

一份好的生图提示词应包括：

1. **用途与读者**：期刊论文中的方法框架图、目标读者、最终版面尺寸或双栏约束。
2. **固定科学内容**：完整的模块顺序、每个分支的输入输出、方向关系、共享图结构、融合与分类链。
3. **明确禁项**：不添加未经说明的损失函数、注意力模块、因果含义、额外组学、预测任务或数据处理步骤；不遗漏指定连线。
4. **视觉设计**：信息层级、布局偏好、配色语义、线型、图例位置、标签语言与文字量。允许视觉变化，但每种方案都要保留同一科学结构。
5. **交付方式**：要求清晰、正视、无裁切、标签可辨，并输出多个布局候选而不是多个科学模型变体。

把“不能改变的模型事实”与“可以尝试的视觉方案”分开写，避免只说“画得漂亮”“顶刊风格”。

## 迭代

每轮先挑出最重要的少量问题，按科学错误、信息层次、可读性排序。若连续两三轮仍重复出现相同连接错误，应冻结模型规范并转到可编辑代码重建。生图草图只是布局参考，不能直接当作论文最终图或科学事实的来源。
